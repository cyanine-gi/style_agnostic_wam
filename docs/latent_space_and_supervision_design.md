# 隐空间与监督设计（世界模型）

> 本文档是**隐空间规格、uv 空间绑定、深度解码/监督分辨率、T/D 网络详细结构、参数-数据匹配与算力时间预算**的独立设计文档，含全部论证结论。
> 完整技术路线（数据管线、训练阶段、域对抗、VLA 集成、显存预算）见姊妹文档 `guideline.md`；两份文档结论一致，冲突时以较新者为准。

---

## 1. 设计问题

确定世界模型的隐空间设计，需同时满足三个目标：

- (a) **动力学可训练**：动作条件转移模型 T 能在隐空间预测未来帧（多步展开不塌缩）；
- (b) **几何可解码**：隐空间（含预测帧隐空间）可解码稠密深度图；
- (c) **域对抗可达**：GRL 能反传进编码器，消灭 sim/real 域信息。

待定量的问题：隐空间特征向量多大？是否有图像 uv（横纵向）的显式绑定？深度监督是否降采样？

硬件约束：单卡 RTX 4070 Ti Super 16GB。

## 2. 结论速览（最终规格）

| 项目 | 规格 |
|---|---|
| 输入分辨率 | 224×224 |
| 编码器 E | DINOv2-S/14（registers 版）初始化，**全程可微调，禁止冻结** |
| 隐空间结构 | patch 级 token，**16×16=256 token × 384 维 = 98,304 维/帧**（bf16 ≈192KB/帧） |
| uv 绑定 | **有，显式**：2D 位置编码绑定每个 token 到固定 14×14 像素块，2D 网格结构全程保留，禁止全局池化 |
| 转移模型 T | 默认 ~20M（8 层/d384）Transformer，从零训练，上限 ≤100M；patch token 加 2D 位置编码，动作/本体感 token 只加时间维编码；详细结构见 §7 |
| 深度解码器 D | **仅接 z（禁止 encoder skip connection）**，卷积上采样头 ~10M，输出 64×64（上限 112×112）稠密 (μ, σ)；详细结构见 §8 |
| 深度监督分辨率 | **掩码感知降采样到 64×64**；满分辨率仅用于评估与可视化 |

## 3. 参照系对比：DINO-WM 与 V-JEPA 2

| | 本设计 | DINO-WM | V-JEPA 2 / V-JEPA 2-AC |
|---|---|---|---|
| 输入分辨率 | 224×224 | 196×196 | 256×256 |
| 空间网格 | 16×16 | 14×14 | 16×16 |
| 隐空间/帧 | 256×384 ≈ **9.8 万维** | 196×384 ≈ **7.5 万维** | 256×1408 ≈ **36 万维** |
| 编码器 | DINOv2-S/14（22M），初始化后**微调** | DINOv2，**冻结**（训练测试全程冻结） | ViT-g/16（约 1B，从零视频 SSL、百万小时视频），**冻结** |
| 位置编码 | 2D sincos（可插值）+ T 内 2D-RoPE | 绝对位置编码 | **3D-RoPE**：特征维按时间/高/宽三轴分段做旋转位置编码 |
| 预测器 | ≤100M，从零 | 19M（6 层 ViT、16 头、MLP 2048），从零 | 300M（24 层、d1024、16 头、block-causal 注意力），从零，62h Droid 数据 |
| 解码器角色 | 深度读出头（μ, σ），动态阶段 stop-grad | 仅事后可视化（16× 空间上采样），**训练不回传**——其实证：解码损失反传进预测器会伤害规划性能（PushT 0.80 vs 0.92） | 无像素解码器（目标是规划与理解） |

要点解读：

1. **三家隐空间在同一数量级**（7.5 万 ~ 36 万维/帧），共同结构是"空间网格 × 数百维通道"——这是几何可解码性与动力学可训练性共同约束出的甜点，本设计的 9.8 万维/帧与其一致。
2. **uv 绑定是三家的共同选择**：没有任何一家把观测压成全局单向量。DINO-WM 的消融显示全局向量化显著掉点（patch 表征保留操作任务必需的空间细节）；V-JEPA 2 用 3D-RoPE 把时间/高/宽三轴显式编码进每个 token。
3. **预测器一律从零训练**——没有现成权重匹配特定动作空间，DINO-WM 与 V-JEPA 2-AC 均如此。
4. **冻结与否是本项目与 DINO-WM/V-JEPA 2 的关键差异**：它们可以冻结编码器，因为没有"从表征中抹除域信息"的需求；本项目需要 Stage 0 深度损失塑形 E、Stage 2 GRL 反传进 E，冻结后两者无处着力，因此 DINOv2 只作初始化。

## 4. uv 绑定的实现设计

**结论：必须有显式 uv 绑定，载体是位置编码。**

- **默认实现**：每个 patch token 携带 2D 位置编码（DINOv2 自带的可插值 sincos），绑定到固定 14×14 像素块；2D 网格结构全程保留，任何环节禁止全局池化。
- **T 内部**：patch token 用 2D 位置编码（2D-RoPE 或可插值 sincos，与 E 的 16×16 网格对齐）；**动作/本体感 token 只加时间维位置编码**（V-JEPA 2-AC 做法）——动作是全局量，不携带空间编码，通过注意力/AdaLN 调制 patch token。
- **可选增强**：解码器入口拼接归一化 uv 坐标通道（帮助深度边缘对齐）；多相机 setup 必须加 camera embedding token。
- **不推荐**：把坐标通道（CoordConv 式）加进 E 的输入——会扰动 DINOv2 预训练特征的分布，得不偿失；位置编码已足够。

## 5. 隐空间大小的权衡原则

1. **空间网格是深度可解码性的硬下限，不可压缩**。网格低于 ~12×12 时，夹爪、线缆、物体轮廓级别的几何在原理上不可恢复。
2. **通道维 d 是软容量，可压缩**。极端证据：bisimulation 风格的表征压缩能把 DINO-WM 的 196×384 压到 196×32（小 10 倍以上）仍保持规划鲁棒性。如需省算力，384→256 的线性压缩是安全的。
3. **"要解码稠密深度图"这一需求排除了极致压缩路线**。object-centric 槽位表征（如 6×128，仅用约 1% 的特征量）能匹配 DINO-WM 的规划性能，但槽位不是空间网格，无法还原稠密深度图，与本项目目标冲突，不采用。
4. **动力学侧的成本用训练技巧吸收，而不是砍网格**：
   - **frameskip（帧跳）**：数据处理时引入帧跳参数（DINO-WM 做法），避免相邻帧过于相似导致平凡复制解；
   - **动态区域损失加权**：按相邻帧 latent 差加权，防止容量浪费在静止背景；
   - **block-causal 注意力**（V-JEPA 2-AC 做法）：控制多帧 token 数的注意力开销。
5. **升级顺序**：显存富余时先升通道 d（384→768），再升输入分辨率，不动网格下限。

## 6. 深度监督分辨率设计（降采样结论）

**结论：深度图降采样后再做监督信号，输出小尺寸深度图（64×64，上限 112×112）。** 理由按重要性排序：

### 6.1 首要理由：防 RGB 捷径（不是省算力）

解码器如果携带 encoder 中间层 skip connection，深度会走"RGB 低层特征 → 深度"的捷径，隐空间 z 里实际不含几何——深度探针失效，"几何在隐空间"的整个论证崩塌。因此 **D 的输入只允许 z**。这一约束确立后，输出分辨率的信息上限就是 16×16 网格加上解码器可学习的平滑先验。

### 6.2 信息上限匹配

- 16×16 网格 → 64×64 输出是 4× 空间上采样（安全区），112×112 是 7×（上限）；
- 超过此范围的高频内容纯属解码器幻觉。强监督 224×224 满分辨率 = 逼解码器对不可恢复的高频拟合，梯度被污染，且 σ 头会被迫把这些不可学残差吸收成"噪声"，损害不确定性校准；
- 佐证：DINO-WM 的解码器做 16× 空间上采样，但它只用于可视化、不反传——与本结论一致。

### 6.3 工程规范

- **掩码感知降采样**：无效像素不参与池化，池化后按有效像素比例重建掩码（有效比例低于阈值的格点整体置无效，阈值默认 0.5，写入 config）；
- 传感器深度、教师深度、掩码三者用同一套降采样流程；
- 多尺度梯度损失在降采样后的目标上照常计算（64×64 → 32×32 → 16×16 → 8×8 四级）；
- **满分辨率（224×224）目标只用于评估指标与可视化**，不进训练损失。

### 6.4 附带收益

- 解码器与监督的显存/算力大幅下降（64×64 vs 224×224，像素数 1/12）；
- σ 更稳定（不被迫吸收不可恢复的高频残差）；
- 与"隐空间瓶颈"的设计哲学一致：迫使几何信息必须经过 z。

### 6.5 分辨率档位的最终结论（56 / 64 / 112 / 224 怎么选）

- **选择原则：监督分辨率 ≈ 隐空间瓶颈的空间带宽**。16×16 网格（14px/patch）折算的空间带宽约为每 3.5~4 像素一个自由度，对应 56²~64²。监督更细（112²/224²）：多余高频进不了 z，只能被 σ 头吸收成噪声，污染不确定性校准；监督更粗：几何容量没有被监督逼满。
- **224²**：仅评估/可视化档位，不进训练损失（既定）。
- **112²**：对训练无信息增量（超瓶颈 7×），解码器 FLOPs 为 64² 的 3~4 倍，不需要。**例外**：仅当未来深度图本身要进推理回路（MPC 打分、抓取点选择、碰撞检查）时才提高输出分辨率；当前规划中深度是训练脚手架与诊断工具，VLA 读 z 不读深度图。
- **56² vs 64²**：信息量等价（3.5× vs 4× 网格带宽）。默认 64²（解码器 16→32→64 两级 2× 转置卷积最工整）；56² 亦可（目标侧 224→56 为干净的 4× 池化）。config 可调。
- **目标降采样用有效像素中位数池化**（而非均值）：保深度不连续边缘、抗飞点；若夹爪等薄结构在 64² 目标里被多数票抹掉，对比最小值池化（偏向更近表面，利于接触几何）。

## 7. 时序递推 T 的详细结构

默认配置 ~20M 参数，对齐 DINO-WM predictor 的 19M 量级。注意：V-JEPA 2-AC 的 300M 预测器对应的是"冻结的互联网级编码器 + 62h Droid"的规模，本项目数据量不对应，不采用。

- **输入序列**：`[z_t 的 256 个 patch token] + [本体感 token ×1] + [动作 token ×k]`。动作块（action chunk，k 步 × 动作维）**逐步 token 化**：每步动作向量独立 MLP 升为 1 个 token，k 步 = k 个 token，禁止整块压缩（已裁决 2026-09-11——整块压缩会让第 1 步预测看到未来动作，与 block-causal 因果语义矛盾，见 `overall_tensor_flow.md` §1.2/§3.2）；动作只进 T 不进 E（既定约束）。
- **主干**：8 层 pre-LN Transformer，d=384，6 头，MLP 隐藏维 4×，GELU。参数量 ≈ 8×12·d² + 动作适配器与输出头 ≈ 18–20M。
- **位置编码**：patch token 用 2D-RoPE（与 E 的 16×16 网格对齐）；动作/本体感 token 只加时间维位置编码；多步展开时加帧索引 embedding。
- **输出**：取 z 位对应的 256 个 token → Linear(d→d) + LayerNorm → ẑ_{t+1}。**残差 delta 预测 + 输出层零初始化**（实现为 ẑ = z + head(LN(x))），使训练初期 ẑ≡z_t（严格恒等起步），显著稳定早期训练。
- **多步训练**：block-causal 注意力，一次前向同时计算 k∈{1,2,4} 步的损失；推理 rollout 时把 ẑ 回喂作为下一步输入，不再依赖 RGB。
- **损失**：per-patch smooth-L1，目标 `sg(z_{t+1})`；动态区域加权（权重 ∝ ‖z_t − z_{t−1}‖）；frameskip ∈ {1,2,4,8} 随机采样。
- **目标稳定器**：Stage 2 联合微调起，目标 z 由 E 的 EMA 副本产生，防止联合训练时目标漂移/表征塌缩（JEPA 系标准做法）。
- **欠拟合时的扩容顺序**（Stage 1 验收门不达标再动）：先加 unroll 步数与 frameskip 课程 → 再 T 深度 8→12 层 → 最后才动宽度 d 384→512。

## 8. 深度解码器 D 的详细结构

- **输入**：仅 z（256×384，禁止 encoder skip connection——防 RGB 捷径，见 §6.1），reshape 为 16×16×384；可选拼接归一化 uv 坐标 2 通道。
- **结构**：1×1 conv 384→256 → 上采样 16→32（2×[conv3×3 + GroupNorm + GELU]，256ch）→ 上采样 32→64（2×[conv3×3 + GroupNorm + GELU]，128ch）。
- **输出头**：3×3 conv → 2 通道（μ = disparity，log σ），log σ clamp 到 [−3, 5] 防塌缩。
- **归一化**：GroupNorm（与 batch 大小无关，小 batch 稳定）。
- **规模**：~10M 参数，单帧前向 ≈5 GFLOPs。

**为什么是卷积而不是 Transformer**（结论如下）：

1. **分工上不需要注意力**：全局上下文与时序推理已在 E 和 T 中完成，D 拿到的 z 已含全局语义与空间绑定，只剩**空间上采样**这一纯局部操作，卷积的局部性/平移等变性正为此设计；
2. **参数与算力效率**：卷积头 ~10M / 5 GFLOPs；Transformer 解码器要么在 64×64=4096 token 上做平方级注意力，要么重学空间上采样先验，在 16GB 显存与 ~30 万帧数据预算下都是浪费；
3. **探针语义**：D 越弱越局部，"D 能从 z 解出深度"越能证明几何在 z 里而非 D 的参数里——与线性探针同一逻辑；
4. **"DPT 式"与卷积不矛盾**：DPT 的 Transformer 是 backbone，其解码头（Reassemble + Refine）本身就是 conv3×3 + 上采样；
5. **欠拟合时的修法**：先加宽通道（256→384），**不得**以接 skip 或加注意力代替——那会把信息通道引回 RGB（§6.1）。

## 9. 参数规模、数据匹配与算力时间预算

### 9.1 数据量估算（精确值以 introspection 为准，`[待本地核实]`）

按每帧 RGB（JPEG ~150–300KB）+ 深度（~200–600KB）+ 小向量 ≈ 0.5–1MB 估：

- 真机 172+45 = **217GB → 约 25万–45万帧**（规划取中值 ~30 万帧）；
- 仿真 8.5+3.0 = **11.5GB → 约 1.5万–4万帧**；
- **域不平衡 ≈ 15:1**：GRL 的 batch 必须 50/50 域均衡（否则判别器躺赢）；Stage 0 采样比例 config 化（默认 50/50，sim 约重复 10–20 epoch——sim 数据干净、分布窄，重复风险低于 real，配强 RGB 增广进一步压低过拟合）。

### 9.2 参数-数据匹配原则

1. **锚定 DINO-WM 区间，不锚定 V-JEPA 2-AC**：DINO-WM 的 19M 预测器在百小时级演示数据上训成；V-JEPA 2-AC 的 300M 背后是冻结的互联网级编码器（百万小时视频 SSL）。~30 万帧数据对应前者。
2. **token：参数比核算**：30 万帧 × 256 token ≈ 7.7×10⁷ token/epoch。T=20M 时单 epoch token/param ≈ 4:1，训 10–30 epoch 达 40–120:1，健康区间；若 T=300M，单 epoch 仅 0.26:1——要么过拟合，要么多花 10 倍时间换不到收益。
3. E 的容量被初始化锁定（22M），不是瓶颈；瓶颈在数据质量与损失设计。
4. 欠拟合时的扩容顺序见 §7 末条（先课程、再深度、最后宽度）。

### 9.3 单帧算力与模块规模

（FLOPs 按 2·P·tokens 经验式估算）

| 模块 | 参数量 | 单帧前向 FLOPs | 训练状态 |
|---|---|---|---|
| E（DINOv2-S/14，261 token） | 22M | ≈11.5 GFLOPs | Stage 0 训练，Stage 1 冻结，Stage 2 小 lr |
| T（8L/d384，264 token） | ~20M | ≈10.5 GFLOPs/步 | 从零训练 |
| D（卷积头，64² 输出） | ~10M | ≈5 GFLOPs | 始终训练（stop-grad 隔离 E/T） |
| 域判别器 | ~1M | 可忽略 | Stage 2 起 |
| EMA/防漂移副本 | 22M | 11.5 GFLOPs（仅前向无梯度） | 永不训练 |

### 9.4 训练时间预算（4070 Ti Super）

算力假设：BF16 张量核峰值 88.2 TFLOPS（dense）、显存带宽 672 GB/s；小模型训练 MFU 按 25–40% 取**有效 25–35 TFLOPS**。关键工程手段：Stage 1 冻结 E 后离线缓存全部帧的 latent（~70GB 磁盘），T 训练直接读缓存，提速约 3 倍。

| 环节 | 训练量 | 单步估算 | 总时间 |
|---|---|---|---|
| 教师深度离线推理 | ~32 万图，DA-V2-L | — | 1.5–2.5 h |
| 隐空间缓存 | 全帧 E 前向（仅推理） | — | 0.5–1 h |
| Stage 0 | ~100K 步（batch32，~1.9 TFLOPs/步） | 0.1–0.25 s | **4–8 h** |
| Stage 1 | ~150K 步（batch16×unroll4，缓存 latent，~3.2 TFLOPs/步） | 0.1–0.3 s | **4–12 h** |
| Stage 2 | ~80K 步（联合+GRL，~3.6 TFLOPs/步） | 0.15–0.35 s | **3–8 h** |
| Stage 3 | Qwen3-VL-2B LoRA，40–80K 步（~80 TFLOPs/步，batch8） | 2–3 s | **1–2 天** |

**Stage 0–2 合计约 1 天，全项目 2–3 天 GPU 时间。** 可行前提：(i) Stage 1 走缓存 latent；(ii) Stage 3 严格 LoRA + 冻结；(iii) 数据管线用预处理 shard + 多 worker 预取（否则 672 GB/s 带宽被 IO 饿死）。

## 10. 与训练流程的接口（摘要）

- Stage 0（静态重建）：E+D 按本文档规格训练，深度损失反传进 E；防漂移锚（冻结 DINOv2 副本特征蒸馏正则）生效；
- Stage 1（动力学）：T 冻结 E 训练，frameskip 与动态区域加权生效；D 共享解码 z_t 与 ẑ_{t+1}，解码损失对 E/T stop-grad；
- Stage 2（域对抗）：GRL 作用于 z_t 与 ẑ_{t+1}；双探针（域探针 + 深度探针）监控；
- Stage 3（VLA）：WAM 对外接口恒定输出 256 个 patch token（WAM 不感知 VLA 内部实现，已裁决 2026-09-11）；VLA 侧 adapter 采用逐 token Linear(384→512)+GELU → space-to-depth 2×2 → 64 token × 2048（已裁决 2026-09-11，见 `guideline.md` §8.1）。可行性先例：已有工作（JEPA-VLA，2026）在单卡上把 V-JEPA2 ViT-L/16 与 Qwen3-VL-2B 双双冻结做 VLA 微调。

细节与验收门见 `guideline_v2.md` §6/§10。
